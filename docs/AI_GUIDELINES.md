# AI Guidelines

This project can only exist at this scale because of generative artificial intelligence like Anthropic's Claude, because the scale of
the project is too big for a single developer to complete it in the given time.

Code can be copy-pasted, and should be copy-pasted if it accelerates development.
But the developer must understand the complete system architecture and the architecture of the corresponding subsystems. With that
approach the developer can act more like an architect without implementing everything by themself. Every developer and every contribution
must never rely on the usage of LLMs, only the deadline should rely on the acceleration and efficiency boost that comes with AI.


**AI should be used as a tool, the developer is responsible for how to use it, but should never depend on it.**


No one cares if 90% of the code-base is generated with AI, if the architectural work behind it is well thought out and the code quality matches the project's standards.
But if the developer loses track on what his code does because LLMs change too much at once it becomes a problem for the project, because this makes long-term
maintainability much harder.

## Usage of the `generated` macro

The project supports a Rust macro `meister-macros::generated` that should be used to mark entire code blocks that were generated by AI. The macro supports documenting 
the model that was used and the model's version. The marker can be removed if the developer changes the corresponding code block substantially, or many incremental
changes to the code block are made. Developers are highly encouraged to use this macro if possible. If it is not possible, then a usual code comment should be used that marks
the section as generated.

```Rust
#[generated(model = ClaudeFable, version = "5")]
fn test() {
    todo!();
}
```

It is not required to mark boilerplate code, code that includes no real logic, typical copy-paste code like reading a file. The decision on what to mark and what not to mark
should be made individually by the responsible developer.

The purpse of this is to monitor the usage of AI, to improve these guidelines, and learn how to use AI in the future.

## Use of ChatBots

Due to the restrictions on agentic AI, AI chat-bots are the main tool for using generative artificial intelligence. There are no restrictions on how to use chat-bots and what chat-bots
to use. The developers are encouraged to discuss theoretical solutions with LLMs or ideally case other developers who know the projects before implementation.
When implementing features or fixing a bug, the usage of LLMs is also allowed and the developers are encouraged to do so if they follow the restrictions layed out by this document.

## Rapid prototyping

For early-stage prototyping, especially for bigger features, it is allowed to use only roughly reviewed code. Many features and the testing of implementation strategies require huge amounts of code to be written, therefore it is okay to copy-paste roughly reviewed code into the project.
But this exception requires careful documentation and testing by hand afterwards if the implementation should be upstreamed. After the project reaches `version 0.1.1`, which puts it into an `ALPHA` stage, code that fits under the rapid AI prototyping rule should live in marked feature branches and will only be upstreamed to main when proper documentation and testing have occurred.

*No one cares if even 99% of the code is written by AI if it runs **stable**, is **well-tested** and has **proper documentation** by hand, and the responsible maintainer **must** have complete understanding of the code and the subsystems it affects.*
## Agentic AI

The usage of agentic AI for implementing features is forbidden. AI agents like Claude Code (or CodeX, Copilot...) are allowed for code analysis, fixing bugs
and planning new features. But the autonomous implementation of complete features without proper review or understanding of the related subsystem is forbidden.


### Fixing bugs by agents

Using AI-agents to fix well specified issues, with proper bug descriptions is allowed. The contributing developer is still fully responsible to review and document
the agent's suggestions, and if necessary improve and change them. The developer is also responsible for ensureing that the AI agent is following the *Code of Conduct* of this
project which includes this document.

## AI and documentation

This project forbids developers from using generative artificial intelligence for generating documentation. The project's allowance of heavy AI usage in the code-base, 
holds the risk despite all savety meassures that developers do not understand their contribution line-by-line. But by requesting extensive documentation in the form of
code comments, documentation comments and documentation files like the one you are reading right now, forces developers to compeletly review their code line-by-line.

LLMs are still allowed as assistive tool while documenting. This includes: Explaining code, generating bullet-points or structure before formulating sentences,
reviewing documentation, improving the writing and naming inside code and documentation and to correct spelling and grammar.
