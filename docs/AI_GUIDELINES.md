# AI Guidelines

> [!NOTE]
> Tools that are referred to as AI in this project are Large Language Models.
> Agents are any kind of autonomous LLM-driven machine that is allowed to change code.

This project was rapidly prototyped and developed with Claude Code (Fable and Opus). This approach enabled this project
to exist as a work-in-progress open-source system and not just a bundle of scripts for cluster orchestration.

For new contributors this means use AI for prototyping, for coding assistance, for designing new features
but be sure to first understand the system of MeisterStack and especially the subsystems you want to change or extend yourself
to be able to correct the LLMs and be able to write documentation yourself.

**AI should be used as a tool, the developer is responsible for how to use it, but should never depend on it.**

Be aware that while this project evolves and the available AI-tools evolve this document could change!

## AI usage for future contributions

- AI should be used for coding assistance.
- AI should be used to improve code quality and documentation.
- AI can be used to prototype huge sections of code.
- AI should be used for distributed systems testing.

- AI must not be used for documentation files like that one.
  Generated documents must be marked as generated documents by a `[!NOTE]`.
- You must not commit code you do not understand.
- You, and not AI are responsible for your contribution and must be able to explain and understand them.
- AI must not be used for chatting, and human conversation for example in Issues and PRs.


## AI usage during prototyping phase

In the early and design phase of the meister-agent AI-tooling was used in a more conservative way. The pace in which the
project evolved was way slower because the design of the architecture was not completed. In this phase most of the code
was either written by hand or copy-pasted and instantly reviewed by the developer. In this phase code snippets that 
were mostly generated by AI were marked with a `#[generated]` macro that does not exist in the current code-base, but may
be introduced in the future.

The second development stage began with the development of the control-plane (cluster and cloud-controller). In this stage
the system was completely designed and coding agents were used to implement and test new features. 
The coding agents got a detailed specification on what to do and how to report back and test the new features, then results
were proofed in the lab before they are committed.
For testing an agent that
had access to an OpenNebula Lab was used, this agent spawned and tested the distributed systems logic by creating VMs with a
specific role in the cluster. This approach enabled rapid prototyping with a relatively stable system as result.
