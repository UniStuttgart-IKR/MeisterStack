# AI Guidelines

This project can only exist at this scale because of generative artificial intelligence like Anthropic's Claude, because the scale of
the project is too big for a single developer to complete it in the given time.

Code can be copy-pasted, and should be copy-pasted if it accelerates development.
But the developer must understand the complete system architecture and the architecture of the corresponding subsystems. With that
approach the developer can act more like an architect without implementing everything by themself. Every developer and every contribution
must never rely on the usage of LLMs, only the deadline should rely on the acceleration and efficiency boost that comes with AI.


**AI should be used as a tool, the developer is responsible for how to use it, but should never depend on it.**


No one cares if 90% of the code-base is generated with AI, if the architectural work behind it is well thought out and the code quality matches the project's standards.
But if the developer loses track on what his code does because LLMs change too much at once it becomes a problem for the project, because this makes long-term
maintainability much harder.

## Future use of AI and LLMs

For changes after the project hit the `BETA` stage, every block in the source code that is generated by LLMs needs to be marked a follows:

```Rust
#[generated(model = ClaudeFable, version = "5")]
fn test() {
    todo!();
}
```

When the project hits it's `BETA` stage AI-Tooling must be used in a way more conservative way to prevent things from breaking, and to
prevent changes were the developer does not understand the system as a hole or the involved subsystems. Nevertheless AI as a tool
can and should be used to develop, test and especially prototype new features, because it just saves time.
